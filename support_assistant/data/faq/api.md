# API документация

## Начало работы с API

Базовый URL: `https://api.example.com/v2`

Для работы с API нужен API-ключ. Получите его в Настройки → API → Создать ключ.

Аутентификация: передайте ключ в заголовке:
```
Authorization: Bearer YOUR_API_KEY
```

## Лимиты запросов (Rate Limits)

| План | Лимит | Период |
|------|-------|--------|
| Free | 100 запросов | в день |
| Pro | 10 000 запросов | в день |
| Enterprise | 10 000 запросов | в минуту |

При превышении лимита API возвращает **429 Too Many Requests**.

### Заголовки лимитов в ответе:
- `X-RateLimit-Limit` — максимум запросов
- `X-RateLimit-Remaining` — осталось запросов
- `X-RateLimit-Reset` — время сброса (Unix timestamp)

### Что делать при 429?

1. Проверьте заголовок `X-RateLimit-Reset` для времени сброса
2. Реализуйте exponential backoff (1с → 2с → 4с → 8с)
3. Проверьте, нет ли утечки API-ключа (другой сервис расходует лимит)
4. Для Enterprise: если расход ниже лимита, но получаете 429 — это может быть проблема инфраструктуры. Обратитесь в поддержку.

**Важно:** Даже на Enterprise-плане может срабатывать burst-лимит при более 1000 запросов в секунду. Используйте очередь запросов.

## Основные эндпоинты

### Проекты
- `GET /projects` — список проектов
- `POST /projects` — создать проект
- `GET /projects/{id}` — получить проект
- `PUT /projects/{id}` — обновить проект
- `DELETE /projects/{id}` — удалить проект

### Данные
- `POST /projects/{id}/data` — загрузить данные
- `GET /projects/{id}/data` — получить данные
- `GET /projects/{id}/analytics` — аналитика

### Вебхуки
- `POST /webhooks` — создать вебхук
- `GET /webhooks` — список вебхуков
- `DELETE /webhooks/{id}` — удалить вебхук

## Коды ошибок

| Код | Описание |
|-----|----------|
| 400 | Неверный запрос (проверьте параметры) |
| 401 | Не авторизован (невалидный API-ключ) |
| 403 | Доступ запрещён (недостаточно прав или план не позволяет) |
| 404 | Ресурс не найден |
| 429 | Превышен лимит запросов |
| 500 | Внутренняя ошибка сервера |
